# GigaChatin1S
Интеграция GigaChat в 1С любой конфигурации для пользовательского режима
GigaChat-ассистент. Руководство администратора

1. Состав решения
Расширение «GigaChat» (не изменяет основную конфигурацию).
Тип объекта	Имена / Назначение
Подсистема	GigaChat (верхнеуровневая, в командном интерфейсе)
Обработки	ЧатGigaChat, НастройкиGigaChat
Константы	ИспользоватьGigaChat, GigaChat_URLСервера, GigaChat_URLАвторизации, GigaChat_API_Модели, GigaChat_API_Чат, GigaChat_API_Чат_V2, GigaChat_API_Файлы, GigaChat_ВерсияAPI
Регистры сведений	GigaChat_Настройки, GigaChat_ОбработанныеСообщенияСВ, GigaChat_КэшМоделей, GigaChat_ИсторияЧатов, GigaChat_ЗагруженныеФайлы
Общие модули	GigaChat_Сервер, GigaChat_ВзаимодействиеСервер, GigaChat_ФоновыеЗадания, GigaChatКлиент, GigaChat_НастройкиПовтИсп, GigaChat_Контекст, GigaChatБезопасноеХранилище и менеджеры перечислений
Регламентные задания	Обновление кэша моделей
2. Включение
1.	Установить расширение.
2.	Назначить роли (см. раздел 3).
3.	Войти под пользователем с ролью GigaChat_Администратор: открыть «Настройки GigaChat» → включить опцию «ИспользоватьGigaChat» → заполнить параметры сервера и авторизации → «Сохранить».
Примечание: при первом включении пустые константы автоматически заполняются значениями по умолчанию; заданные вручную значения не перезаписываются. Опция глобальная: включение выполняется один раз на базу. При выключенной опции формы настроек заморожены, обработчики не подключаются.
3. Роли и видимость
Роль	Назначение
GigaChat_Основная	Видимость раздела, работа с чатом и персональными настройками.
GigaChat_Администратор	Управление опцией включения и серверными константами; назначается поверх основной.
4. Настройки
4.1. Параметры сервера (константы)
URL сервера и авторизации, пути API (модели, чат, файлы), версия API.
Важно: Константа GigaChat_API_Файлы доступна для редактирования на форме настроек. Файловый эндпоинт существует и используется в рамках API V1 (/v1/files), независимо от версии чата. Значение по умолчанию устанавливается модулем GigaChat_НастройкиПовтИсп при первом включении. Защита от случайных правок: серверная группа открывается только для чтения; снятие защиты — команда меню «Ещё», доступна только администратору GigaChat.
4.2. Авторизация (регистр GigaChat_Настройки)
Base64-ключ, Scope, RqUID. При первом открытии формы с пустыми настройками RqUID генерируется автоматически. Кнопка «Проверить настройку» выполняет тестовую авторизацию и запрос списка моделей. Особенность: данные авторизации при успешной проверке сохраняются в регистр без отката — это осознанное поведение для упрощения первичной настройки.
4.3. Режим работы
Иерархия: персональная настройка пользователя → глобальная → значение по умолчанию. Персональный режим задаётся в форме настроек; сброс персонального значения возвращает пользователя к глобальному режиму. Режим определяет интерфейс при старте: окна системы взаимодействия, плавающая форма независимого чата или оба одновременно.
4.4. Кэш моделей
Регистр GigaChat_КэшМоделей обновляется регламентным заданием. Ошибки задания не прерывают его работу: следующая попытка выполняется по расписанию.
4.5. Хранилище файлов независимого чата
•	Бинарники файлов хранятся в ХранилищеЗначения внутри базы 1С, привязаны к пользователю и идентификатору сессии чата (регистр GigaChat_ЗагруженныеФайлы).
•	При отправке вопроса файлы загружаются на сервер GigaChat через POST /v1/files (multipart/form-data, purpose=general). GigaChat возвращает идентификатор файла (file-...).
•	В запросе к /v1/chat/completions файлы привязываются к последнему сообщению пользователя через поле attachments (массив идентификаторов).
•	После успешного получения ответа файлы удаляются с сервера GigaChat через DELETE /v1/files/{id}.
•	Аварийный откат (Rollback): при ошибке запроса к GigaChat выполняется полный откат: файлы удаляются с внешнего сервера и помечаются как незалитые в регистре 1С. При следующей отправке они загрузятся заново. Осиротевших записей не остается.
•	Лимит размера файла: 50 МБ (контролируется и на клиенте, и на сервере).
•	Поддерживаемые форматы: pdf, docx, xlsx, csv, png, jpg, jpeg, webp.
5. Журнал регистрации и диагностика
Событие ЖР	Содержание
GigaChat_Старт	Ошибки инициализации при старте сеанса.
GigaChat_Инициализация	Создание пользователя-бота, личных обсуждений, приветствий.
GigaChat_Фон	Работа фонового цикла и ядра обработки, ответы по сообщениям.
GigaChat_СВ	Ошибки взаимодействия с сервером системы взаимодействия.
GigaChat_Диагностика	Служебные сообщения клиентских обработчиков.
GigaChat JOB: ...	Обновление кэша моделей.
Регистр GigaChat_ОбработанныеСообщенияСВ: статус «Успех» или «Ошибка» с текстом ошибки по каждому сообщению. Сообщение со статусом «Ошибка» автоматически не повторяется; для принудительного повтора удалите его запись из регистра.
6. Аварийные процедуры
•	Недоступность сервера СВ: в журнале предупреждение «Сервер СВ недоступен, обеспечение бота отложено». Действий не требуется: после восстановления связи фоновый цикл подберет необработанные сообщения автоматически.
•	Зависшие сеансы в файловом варианте: в файловой базе СВ-компонент и фоновые задания выполняются в клиентских процессах; зависший процесс может вызывать ошибки «Timer Expired». Лечение: завершить все процессы 1С и открыть базу заново.
•	Ошибки загрузки файлов: благодаря механизму rollback (п. 4.5) повторная обработка не приводит к дублированию файлов или списанию лимитов. Дубли ответов штатно невозможны.
7. Требования к окружению
•	Платформа 1С 8.3.27 и выше (разработка и тестирование: 8.5.4, совместимость 8.3.27).
•	Сетевой доступ из среды 1С к URL авторизации и сервера GigaChat.
•	Поддерживаются файловый и клиент-серверный варианты (в файловом варианте учитывать, что СВ и фоновые задания живут в клиентских процессах).
•	Для панелей обсуждений на формах объектов необходима штатная подсистема БСП «Обсуждения» в основной конфигурации.
8. Чек-лист внедрения и отката
•	Внедрение: установка расширения → назначение ролей → включение опции → заполнение параметров → «Проверить настройку» → тест (личный чат, слово-обращение в общем чате, панель объекта) → наблюдение журнала первые сутки.
•	Откат: выключить опцию ИспользоватьGigaChat (функциональность гасится мгновенно без удаления расширения) либо снять расширение целиком. Данные регистров и констант сохраняются для возможного повторного включения.
4.2. Как получить ключи авторизации GigaChat
Для работы расширения необходимы учетные данные из кабинета разработчика Сбер. Получите их по следующей инструкции:
Регистрация и вход
Перейдите в Кабинет разработчика GigaChat. Войдите в систему под своей учетной записью 
Сбер ID (для физических лиц) или корпоративной учетной записью (для юридических лиц).
Создание проекта
Перейдите в раздел «Проекты» и нажмите «Создать проект».
Дайте проекту понятное имя (например, 1C_GigaChat_Assistant) и нажмите «Создать».
Подключение API
Откройте созданный проект.
В разделе «Продукты» нажмите «Добавить продукт» и выберите «GigaChat API».
Примите условия использования (оферту), если система запросит подтверждение.
Получение ключа авторизации (Base64)
В настройках проекта перейдите во вкладку «Учетные данные» (или «Доступы»).
Найдите поле «Ключ авторизации» (Authorization key).
Важно: Это поле уже содержит готовую Base64-строку (которая представляет собой закодированную пару ClientID:Secret).
Просто скопируйте эту строку целиком и вставьте её в поле «Base64-ключ» в настройках 1С. Никакого дополнительного кодирования или склеивания выполнять не нужно.
Настройка Scope (Область доступа)
В поле «Scope» настроек 1С укажите значение, соответствующее типу вашего аккаунта:
GIGACHAT_API_PERS — для аккаунтов физических лиц.
GIGACHAT_API_CORP — для аккаунтов юридических лиц.
Настройка разрешенных IP-адресов (Опционально, для повышения безопасности)
В разделе «Учетные данные» может присутствовать блок «Разрешенные IP-адреса».
По умолчанию, если этот блок пуст или отсутствует, сервер Сбера принимает запросы с любого IP-адреса (при условии корректного ключа).
Рекомендация: Если вы хотите повысить безопасность и ограничить доступ к API только вашим сервером, добавьте в этот список внешний (белый) IP-адрес вашего сервера 1С или прокси-сервера. Если вы его добавите, запросы с других IP будут отклоняться с ошибкой 403 Forbidden.
Проверка в 1С
Вставьте скопированный Base64-ключ и Scope в форму «Настройки GigaChat».
Нажмите кнопку «Проверить настройку». Если настройка верна, система успешно получит токен и список доступных моделей, а данные сохранятся в регистр.
